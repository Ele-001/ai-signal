# 0.1.4 任务识别与刷新

日期：2026-10-28。

## 原因

旧版冷启动只解析会话文件最后约 8 MiB 及头部元数据。持续运行的长任务，其开始事件可能已经落在尾部范围之前，导致启动时没有当前生命周期信息，任务被遗漏。重新加载界面不能修复这个问题。

## 修改

- 启动时逐行完整恢复近 24 小时更新过的本机会话状态；随后每 3 秒只读取新增完整行。
- 文件尾部尚未写完的记录保留到下一次读取，避免丢失状态切换。
- 最近会话上限由 32 提高至 512，超限明确提示；单条记录最多 64 MiB，避免无限内存占用。
- 某份记录读取失败时继续识别其他记录，并提示同步未完成。
- 「任务」和「连接」页面增加“刷新任务”、同步进度及最近成功同步时间。刷新重新读取会话记录，保留本地手动任务和设置；不会改变 Codex 的执行状态。
- 刷新、自动扫描使用同一个串行缓存入口，避免两个扫描同时修改状态。刷新也会更新已经结束的现有任务。
- 保留明确待回答、锁屏和真实连接故障的红灯保护。无新消息不会按时间转红。

## 验证

- Rust 28 项通过，2 项真实历史测试默认按需执行。
- 前端 7 项通过，TypeScript、Vite 和 Tauri macOS arm64 正式构建通过。
- 新回归测试覆盖两份超出旧尾部读取范围的运行记录、超过 8 MiB 的单条正常记录、半行写入后补全、增量完成与冷启动完成状态。
- 单独执行真实本机会话回放：三个选定会话均识别成功，当时两项运行，一项本轮结束且仍有待回答问题；未把待回答任务强制改绿。
- 真实历史仅用于本机只读验证，不包含在代码或交付包中。

桌面实机检查：安装并启动 0.1.4 后自动显示三项真实本机任务：两项运行、一项等待回答。点击“刷新任务”后显示同步中并禁用重复点击；完成后复查任务与时间。未手工补录任务，未点击“已检查”改变任务状态。

## 边界

仅识别已连接且可读取的本机会话，不保证覆盖云端、其他设备和所有 Codex Desktop 状态。超过 24 小时完全未写入的会话仍在当前发现范围外。首次读取大历史可能需要数秒。Windows 未实机验证。此版未增加其他设备同步或远程会话读取权限。
