# 0.1.5 历史问题误报与手动确认

日期：2026-10-28。

## 根因与修复

本机历史解析此前只把 `event_msg.user_message` 当作普通用户回复。实际 Codex Desktop 也使用 `response_item.message`（role 为 user）。后者的普通消息没有结束旧问题，因此几天前的提问会在冷启动完整回放后重新变红。上一版将这项误报误认为真实待回答事项。

现在两种记录中的真实用户请求均会结束先前遗留的待回答记录；普通任务继续运行时保持绿闪，已结束时按来源状态显示完成。取消轮次时清除该轮等待及工具锁屏记录。仅日期、浏览器、环境等上下文记录不会被误当成用户回答。

异步提问的 `accepted` 仍只表示问题已受理；没有真实回复时，本轮结束不会清除提问。结构化回复继续按题目逐项解除，其他未回答问题保持红灯。

## 已处理

本机兼容识别的待回答事项增加“已处理”，同时保留移除任务入口。提示文案改为“检测到待回答记录，请在 Codex 核对”。

“已处理”只确认当前问题的调用标识，并保存在本机连接设置中。刷新和重启不会把同一次问题重新点红；新调用标识的问题仍正常提醒。确认后按来源最近明确的运行、完成或空闲状态更新，不强行把所有任务标成运行。不会代替 Codex 中的回答或审批，不会解除实际锁屏、连接故障或其他待处理任务，也不会伪造任务进展时间。来源明确上报的审批不使用这个兼容识别兜底。

当前最多保留 512 条已处理问题标识，达到上限会明确报错，不会静默忽略后续问题。旧配置自动兼容；未增加依赖。
